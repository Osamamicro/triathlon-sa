a Release publish served with `ASPNETCORE_ENVIRONMENT=Production`. Every page

(commands reproduced at the bottom).

## Observation (not gating, not fixed)

`/en/events/riyadh-sprint-2026`, `/en/governance`, `/ar/events/riyadh-sprint-2026`
and `/ar/governance` each lose 2 accessibility points to a single audit:
`heading-order` ("Heading elements are not in a sequentially-descending
order"). Since the gate (>= 95) is met on every page, no `src/` change was
made here — heading order is explicitly in the `stf-visual-qa` a11y-tree
checklist for the parallel matrix pass (Steps 5-6 of this brief), so it will
be caught and reported there. Flagging it here so it isn't lost.

## No fixes were needed, so no before/after — the "before" numbers above are
also the "after" numbers. If a future change regresses a page below the
gate, re-run `tools/lighthouse/run.sh` against a fresh Release publish and
apply the standard levers (`font-display: swap`, preload only above-the-fold
faces, `fetchpriority="high"` + explicit dimensions on the hero mark,
`loading="lazy"` + dimensions below the fold, no layout shift from the stat
band, long cache headers on fingerprinted assets, response compression) —
never suppress an accessibility audit.

## Commands used

```bash
# Build and serve a Release publish
dotnet publish src/Triathlon.Web -c Release -o "$SCRATCH/perf/publish"
cd "$SCRATCH/perf/publish" && ASPNETCORE_ENVIRONMENT=Production \
  ASPNETCORE_URLS=http://localhost:5080 \
  Database__MigrateOnStartup=true Database__SeedContent=true \
  Seed__AdminEmail=admin@triathlon.sa Seed__AdminPassword='Qa-Run-2026!Strong' \
  dotnet Triathlon.Web.dll

# Lighthouse mobile gate, two runs per page, best kept
tools/lighthouse/run.sh http://localhost:5080 "$SCRATCH/perf/lh-before"
```

`tools/lighthouse/run.sh` resolves Chromium via
`require('playwright').chromium.executablePath()` (Playwright's own browser,
already installed in the scratchpad's `node_modules`) so it matches the
Chromium the rest of the QA tooling uses; `--chrome-path` is accepted by the
installed `lighthouse@13.4.1` CLI even though it isn't listed in `--help`
(chrome-launcher reads it straight off the parsed flags) — verified working
by inspecting `environment.hostUserAgent` in the resulting JSON
(`HeadlessChrome/152...`, matching the pinned Playwright Chromium build).

Raw JSON reports are not committed (per brief instruction); this table was
generated from the reports under the scratchpad's `perf/lh-before/` with a
`node -e` script pulling `categories.performance/accessibility.score` and
the `largest-contentful-paint` / `cumulative-layout-shift` /
`total-blocking-time` audit `displayValue`s.
