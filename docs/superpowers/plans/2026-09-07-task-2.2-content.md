# Task 2.2 — Documents, Rules, Training guides, Statistics, Governance, Pages, News, athlete registration (step-level plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every remaining brief section — governance & documents library, rules, training guide, statistics, join / become an athlete (with the real registration form), plus news and contact — renders from the database in English and Arabic, and the dashboard login page is bilingual before client review 1.

**Architecture:** Same shape as Task 2.1: entities under `Domain/{Documents,Stats,Content,Crm}`, EF configurations, one migration pair per sub-task, seeders transcribed from the prototype, one service per aggregate, Razor Pages with `Bi(en, ar)`. CMS pages are `Page` + ordered `PageBlock` rows rendered by block partials; dedicated pages (rules, training, governance, statistics) render their aggregate and then any trailing blocks for that slug. Athlete registration posts to `POST /api/register` (antiforgery, rate limit, Turnstile when configured) and creates a Pending `Athlete`.

**Tech Stack:** .NET 10 · Razor Pages · EF Core 10 · xUnit + Testcontainers · MailKit (`IEmailSender` exists) · Cloudflare Turnstile (HTTP verify).

**Spec:** `docs/superpowers/specs/2026-09-06-triathlon-platform-design.md` §6–§7, §9b; Task 2.2 in `docs/superpowers/plans/2026-09-06-triathlon-platform-ultra-plan.md`; prototype pages `governance.html`, `rules.html`, `training.html`, `stats.html`, `join.html`, `register.html`; data in `assets/js/data.js`.

## Decisions recorded by this plan

1. **Block model.** `PageBlock.Type ∈ { Hero, RichText, Steps, Cards, Table, Faq, Cta, Clubs }`; `Variant` is a free string the partials understand (`Cards`: `grid-3` default, `grid-4`, `pathway`, `muted`; `Hero`: `page` default). Repeating content is `ItemsJson` (`List<BlockItem>`), stored as text on both providers. Table cells whose English and Arabic text are identical (numbers, codes) render with the `mono` class, which reproduces the prototype's styling without a per-cell flag.
2. **Dedicated pages + trailing blocks.** `/rules`, `/training`, `/governance`, `/statistics` render their aggregate first and then the blocks of the `Page` with the same slug, if one exists. `/join`, `/contact` and any future CMS page are served by one generic `Content.cshtml` at `/{culture}/{slug}` (lowest routing precedence; unknown slug → 404).
3. **Navigation from the database.** `NavItem(Location = Header | FooterCompete | FooterInvolved)`; `_Header`/`_Footer` read `ContentService.NavigationAsync`. Pages are tagged `CacheTags.Site`, so a navigation publish evicts everything.
4. **Facets** for the documents library are computed from published documents (`category → count`, `year → count`) in one query pair; the page renders server-side filters (`?category=&year=`) like the events page.
5. **Download counters** are recorded by `GET /documents/{id}/download` (and `/rules/{id}/download`, `/training/{id}/download`) with `ExecuteUpdateAsync` then a 302 to the file; never cached.
6. **Athlete registration** creates `Athlete(Status = Pending)` with the prototype form's fields; national ID, emergency contact and licence issuing arrive with the CRM in Week 5. The confirmation email is sent inline through `IEmailSender` (the logging sender in dev/tests); Week 5 moves it to a Hangfire job.
7. **Turnstile** is on when `Turnstile:SiteKey` and `Turnstile:SecretKey` are set; then the widget renders on the form, the CSP allows `https://challenges.cloudflare.com`, and `POST /api/register` verifies the token server-side. Unset (dev, tests) → no widget, no verification, a log line at startup.
8. **Dashboard culture** comes from a cookie (`CookieRequestCultureProvider`, added after the route provider so public URLs still win). A tiny endpoint `GET /dashboard/culture/{culture}?returnUrl=` sets it. Only the login/lockout/access-denied/not-found/error pages are localised now (`Resources/DashboardStrings.{en,ar}.resx`); Week 4 does the rest.
9. **Kpi keys** are stable identifiers from the prototype (`athletes`, `elite`, …); `ShowOnHome` + `SortOrder` decide the home band; `Source = Computed` is reserved for the Week 4 nightly job and is display-only now.

public async Task<string?> RecordDownloadAsync(DownloadKind kind, Guid id, CancellationToken ct)
{
    switch (kind)
    {
        case DownloadKind.Document:
            var d = await db.Documents.Where(x => x.Id == id && x.IsPublished).Select(x => x.FilePath).SingleOrDefaultAsync(ct);
            if (d is null) return null;
            await db.Documents.Where(x => x.Id == id).ExecuteUpdateAsync(s => s.SetProperty(x => x.Downloads, x => x.Downloads + 1), ct);
            return d;
        // Rule and Guide: same shape against db.Rules / db.TrainingGuides (guide FilePath may be null → return null)
    }
}
