# Task 4.2 — CRM screens, admin panel, Week 5 gate and the session chain (step-level plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The membership desk gets screens: athletes searched and filtered on the server, one athlete opened and approved or rejected in two clicks, event registrations listed and exported, clubs and contacts maintained, an email blast composed against a live audience count, users invited and disabled, a dashboard-wide activity feed that shows only what the signed-in role may see, and an Overview that leads with the work waiting. Then the Week 5 gate is proven end to end in both directions on local evidence, `v0.3.0` is tagged, and the session is chained.

**Architecture:** Three pieces of page chrome are written once (Task 4.2.A) and reused by every CRM screen: `FilterBar` (the row of filters, the result count and the export button), `PagedTable<TItem>` (a `MudTable` over a `PagedResult<T>` with server paging) and `DetailShell` (the read-mostly record page — `EditShell` is for forms, and a CRM record is a page of facts with an action bar). Every screen maps 1:1 onto the Task 4.1 services (`CrmService`, `ContactsService`, `EmailBlastService`, `EventsService`, `ContentService`, `StaffAccounts`, `IActivityQuery`) through `DashboardScope.RunAsync`; screens hold no persistence logic and never touch `AppDbContext`. Interactive server rendering; every string from `DashboardStrings`.

**Tech Stack:** Blazor interactive server, MudBlazor 9.9.0, the Task 3.1 kit (`BilingualField`, `BilingualRichText`, `SlugField`, `MediaPicker`, `FileUpload`, `PublishBar`, `ConfirmDialog`, `ActivityDrawer`) and the Task 3.2 chrome (`EntityTable`, `EditShell`, `ItemsEditor`, `ReorderList`), ASP.NET Core Identity (`UserManager<AppUser>`), Hangfire 1.8.25, bUnit 2.9.0, playwright-cli for evidence.

**Spec:** `docs/superpowers/plans/2026-09-06-triathlon-platform-ultra-plan.md` Task 4.2 (lines 76-88, 200-215) and the Week 5 gate; `docs/superpowers/specs/2026-09-06-triathlon-platform-design.md` §2 (users and roles), §6.3 (flows), §6.4 (PDPL), §9b; `docs/HANDOVER.md` §7 (chain), §8 Week 5, §9 Week 5 carry-overs; `docs/qa/2026-09-08-week4-dashboard.md` (F7-F14); `docs/superpowers/plans/2026-09-08-task-4.1-crm-domain-services.md` (its Carry-overs table and Decisions 1-16 — **read both before starting**); `docs/superpowers/plans/2026-09-08-task-3.2-content-screens.md` (the screen pattern this extends); `.claude/agents/stf-dashboard-ux.md`.

## Global Constraints

As in the Task 3.2 plan. Restated because they bind every step here:

- Screens call services only; no `AppDbContext` in a `.razor` file. Every read-for-edit and every save runs in its own DI scope through `DashboardScope.RunAsync` (`Areas/Dashboard/DashboardScope.cs`), so a refused save never leaves a dirty context on the circuit.
- A `ContentValidationException` from a save is caught by the page and rendered through `EditShell.Handle(L, ex, out banner, fieldErrors)`, which after Task 4.2.A fans out **every** `ex.Errors` entry (Task 4.1 Decision 11), so a form marks all its bad fields at once. Anything else is caught by `EditShell.HandleUnexpected` (added by the Week 4 QA commit).
- Policies: every CRM screen is `[Authorize(Policy = Policies.Crm)]`; Clubs stays `[Authorize(Policy = Policies.Content)]` because `ContentService` owns it (Task 4.1 Decision 9); Users, Activity and Settings are `[Authorize(Policy = Policies.Admin)]`. ## Decisions recorded by this plan

1. **Two list patterns, not one.** `EntityTable` (Task 3.2.A) filters in memory and is right for content, where the whole table is a screenful — it has no toolbar or row-action fragments and requires `Search`, `Columns`, `Headers`, `EditHref` and `IsPublished`. CRM lists grow without bound, so they get `PagedTable<TItem>` over `PagedResult<T>` with server paging and `FilterBar` above it. `EntityTable` is **not modified**; the two coexist and each component's file header says which is which. Clubs, whose list is six rows, stays on `EntityTable`.
2. **A CRM record is a page of facts, not a form.** `DetailShell` renders a definition list of read-only facts, an action bar, an "Edit details" panel that expands into the actual fields, and the `ActivityDrawer`. Destructive actions go through `ConfirmDialog`; Reject and Suspend collect the officer's reason in the dialog, so `ConfirmDialog` gains an optional reason field and a `ShowWithReasonAsync` overload while its existing `ShowAsync` signature is untouched.
3. **The Users screen is a plain `MudTable`, not `EntityTable`.** `EntityTable` has no toolbar fragment (Users needs an "Invite user" dialog), no row-action fragment (Users needs a role menu, a disable/enable switch and a "send reset link" button) and a mandatory `IsPublished`, which is meaningless for an account. Bending it to fit would make every content screen carry parameters only Users uses. Users is one screen with about sixty lines of its own `MudTable` markup; that is cheaper than the generalisation.
4. **The Users screen never shows or sets a password.** `StaffAccounts.InviteAsync` creates the account with a random 32-character password that is generated, used once and discarded — nobody, including the administrator, ever sees it — and the invitee receives a password-*reset* link generated inside `StaffMailJob`, so no token reaches Hangfire storage either. "Send reset link" repeats that for an existing account. Disable is a permanent lockout (`LockoutEnd = DateTimeOffset.MaxValue`) plus a security-stamp bump; because a bumped stamp only bites at the next revalidation, `IdentityRevalidatingAuthenticationStateProvider.RevalidationInterval` drops from 30 minutes to **5 minutes** in the same task, and the screen's hint says a disabled user is cut off within five minutes. An administrator cannot disable themselves, cannot remove their own SuperAdmin role, and cannot remove the last SuperAdmin.
5. **The invite and reset pages are server-rendered like every other account page.** `Areas/Dashboard/Pages/Account/ResetPassword.razor` is a static SSR `EditForm` in the shape of the existing `ChangePassword.razor` — no `@rendermode InteractiveServer`. An anonymous page that takes a one-use token has no business opening a SignalR circuit, and the existing account pages already prove the SSR form pattern works with `IdentityRedirectManager` and `StatusMessage`.
6. **Activity is filtered by policy, not by hope.** `ActivityScopes` maps **every** `ActivityLog.Entity` value this application writes — all twenty, enumerated by name — to the policy that may read it. `IActivityQuery.FeedAsync` takes the allowed entity names and returns nothing when the list is empty: fail closed. An entity name the map does not know is Admin-only, so a future entity is private until somebody classifies it, and a grep-driven test fails the build if a new `ApplyAsync("X", …)` or `LogAsync("X", …)` appears anywhere under `src/Triathlon.Web` without a classification.
7. **Entity and action labels are bilingual in code, not in resx.** F11 asks for translated `Entity`/`Action` values in the activity feed. That is twenty entity names and about twenty action verbs: forty resx pairs for a fixed technical vocabulary that no editor ever changes, sitting next to 300 keys that are genuinely editorial. `ActivityLabels` is a static bilingual lookup beside `ActivityScopes`, in the same file family and covered by the same completeness test, and it falls back to the raw value for anything it does not know. The precedent is `AthleteCategories.Arabic`.
8. **Draft preview is a signed link that carries its own expiry.** `PreviewTokens` protects `"{entity}:{id}:{expiresAtUnixSeconds}"` with the `content.preview` purpose. The expiry is **inside the payload and checked against the injected `TimeProvider`**, not delegated to `ToTimeLimitedDataProtector`, for one reason: a time-limited protector uses its own internal clock, so a test could never advance past it. With the expiry in the payload, `PreviewTokensTests` advances `FakeTimeProvider` by 31 minutes and asserts the token is refused. Lifetime is 30 minutes. `/{culture}/preview/{token}` renders the draft with `no-store` and `X-Robots-Tag: noindex, nofollow`. The token *is* the authorisation — a 30-minute link to one unpublished page is the right trade for letting an editor send a draft to a colleague — and `PreviewAfterPublish` in `EditShell` becomes a real "Preview draft" button.
9. **Media gets a hard delete and a nightly orphan report.** `MediaService.PurgeAsync(Guid id, ct)` removes a *soft-deleted* asset's row and its files, refusing while the path is still referenced by any document, rule, guide, event hero, event results file, gallery image, page block or news post. `MediaSweepJob` runs nightly and **logs, never deletes**, files on disk with no catalog row, so an administrator gets a report rather than a surprise.
10. **Overview leads with work, not with counts.** The first tile is pending applications with a direct link to the filtered list; the second is the next three events with their registration fill; the third is the last blast. The Week 4 tiles keep their places below.
11. **Registrations are one screen with an optional event filter**, not a tab inside the event editor: the desk's question is usually "who is entered for X" but sometimes "where is this person entered", and one screen answers both. The event edit screen gets a link to it, pre-filtered.
12. **Clubs live in the Content navigation group** (Task 4.1 Decision 9). The CRM group is Athletes · Registrations · Contacts · Email. Putting Clubs under CRM would put a `Policies.Content` service behind a `Policies.Crm` page.

```csharp
using System.Globalization;
using Triathlon.Web.Services;

namespace Triathlon.Web.Areas.Dashboard;

/// <summary>
/// The four formatting decisions every dashboard screen otherwise re-implements: pick a language,
/// join a list, print a timestamp in Riyadh, and print an em dash where there is nothing to print.
/// The culture question itself is answered once by <see cref="DashboardCulture.IsArabic"/>.
/// </summary>
public static class DashboardText
{
    /// <summary>What a screen shows where a value is genuinely absent.</summary>
    public const string Dash = "—";

    public static string Bi(string en, string ar) => DashboardCulture.IsArabic ? ar : en;

    public static string? Bi(string? en, string? ar) => DashboardCulture.IsArabic ? ar : en;

    /// <summary>
    /// A comma-joined list in the reader's own punctuation: Arabic uses U+060C, not the Latin comma,
    /// and a hard-coded ", " is the kind of detail that makes an Arabic page read as a translation.
    /// </summary>
    public static string Join(IEnumerable<string> values) =>
        string.Join(DashboardCulture.IsArabic ? "، " : ", ", values);

    public static string Date(DateTimeOffset? at) => at is null
        ? Dash
        : at.Value.ToOffset(EventsService.RiyadhOffset)
            .ToString("yyyy-MM-dd HH:mm", CultureInfo.InvariantCulture);

    public static string Date(DateOnly? date) =>
        date?.ToString("yyyy-MM-dd", CultureInfo.InvariantCulture) ?? Dash;
}
```

```csharp
    /// Turns a refused save into places to show it. A refusal keyed to the record itself
    /// (<c>Field == "Id"</c> — not found, erased, still in use) becomes the banner; every other field
    /// is keyed by name for the caller to show inline and is also listed by the summary above, so

    /// Since Week 5 a refusal carries <see cref="ContentValidationException.Errors"/> — every field the
    /// save objected to — and all of them are marked at once instead of one reload at a time.
    /// </summary>

        ArgumentNullException.ThrowIfNull(fieldErrors);

        banner = null;

        foreach (var error in ex.Errors)

            if (error.Field is "Id")
            {
                banner = message;
            }
            else
            {
                fieldErrors[error.Field] = message;
            }
        }
```

```razor
    /// <summary>
    /// The filter lives in the query string, not in a field: the desk bookmarks "pending
    /// applications", the Overview tile links straight to it, and the browser's back button behaves.

    protected override async Task OnParametersSetAsync()
    {
        filter = new AthleteFilter(
            Q: Q,
            Status: Enum.TryParse<AthleteStatus>(Status, out var status) ? status : null,
            ClubId: Club,
            Category: Category,
            CityKey: City,

    private async Task LoadAsync()
    {
        loading = true;

        var data = await Scope.RunAsync(async sp => (
            Page: await sp.GetRequiredService<CrmService>().SearchAsync(filter, CancellationToken.None),
            Clubs: await sp.GetRequiredService<ContentService>().ClubsForEditAsync(false, CancellationToken.None),
            Cities: await sp.GetRequiredService<EventsService>().CitiesAsync(CancellationToken.None)));

        result = data.Page;
        clubs = data.Clubs;
        cities = data.Cities;
        loading = false;
    }

    private void Go(
        string? q = null, AthleteStatus? status = null, Guid? club = null, string? category = null,
        string? city = null, bool? deleted = null, int? page = null)
    {
        var query = new Dictionary<string, object?>(StringComparer.Ordinal)
        {
            ["q"] = Blank(q ?? filter.Q),
            ["status"] = (status ?? filter.Status)?.ToString(),
            ["club"] = club ?? filter.ClubId,
            ["category"] = Blank(category ?? filter.Category),
            ["city"] = Blank(city ?? filter.CityKey),
            ["deleted"] = (deleted ?? filter.DeletedOnly) ? true : null,
            ["page"] = page is > 1 ? page : null,
        };

        Nav.NavigateTo(Nav.GetUriWithQueryParameters(query));
    }

    // Every filter change resets to page one: staying on page 4 of a filter that now has one page
    // would show an empty table and look broken.
    private Task OnSearchAsync(string? value) { Go(q: value, page: 1); return Task.CompletedTask; }
    private Task OnStatusAsync(AthleteStatus? value) { Go(status: value, page: 1); return Task.CompletedTask; }
    private Task OnClubAsync(Guid? value) { Go(club: value, page: 1); return Task.CompletedTask; }
    private Task OnCategoryAsync(string? value) { Go(category: value, page: 1); return Task.CompletedTask; }
    private Task OnCityAsync(string? value) { Go(city: value, page: 1); return Task.CompletedTask; }
    private Task OnShowDeletedAsync(bool value) { Go(deleted: value, page: 1); return Task.CompletedTask; }
    private Task OnPageAsync(int value) { Go(page: value); return Task.CompletedTask; }

    private Task ResetAsync()
    {
        Nav.NavigateTo("dashboard/crm/athletes");
        return Task.CompletedTask;
    }

    /// <summary>The export carries the filter the officer is looking at, so the file matches the screen.</summary>
    private string ExportHref
    {
        get
        {
            var parts = new List<string>();
            if (!string.IsNullOrWhiteSpace(filter.Q)) parts.Add("q=" + Uri.EscapeDataString(filter.Q));
            if (filter.Status is { } status) parts.Add("status=" + status);
            if (filter.ClubId is { } club) parts.Add("clubId=" + club);
            if (!string.IsNullOrWhiteSpace(filter.Category)) parts.Add("category=" + Uri.EscapeDataString(filter.Category));
            if (!string.IsNullOrWhiteSpace(filter.CityKey)) parts.Add("cityKey=" + Uri.EscapeDataString(filter.CityKey));

            return "/dashboard/exports/athletes" + (parts.Count == 0 ? "" : "?" + string.Join('&', parts));
        }
    }

    private string StatusLabel(AthleteStatus status) => status switch
    {
        AthleteStatus.Pending => L["Pending"],
        AthleteStatus.Approved => L["Approved"],
        AthleteStatus.Rejected => L["Rejected"],
        AthleteStatus.Suspended => L["Suspended"],
        _ => status.ToString(),
    };

    private static Color StatusColour(AthleteStatus status) => status switch
    {
        AthleteStatus.Pending => Color.Warning,
        AthleteStatus.Approved => Color.Success,
        AthleteStatus.Rejected => Color.Error,
        _ => Color.Default,
    };

    private string CategoryLabel(string category) => DashboardCulture.IsArabic
        ? AthleteCategories.Arabic(category)
        : category;

    private static string? Blank(string? value) => string.IsNullOrWhiteSpace(value) ? null : value;
}
```

```csharp
using Hangfire;
using Microsoft.AspNetCore.Identity;
using Triathlon.Web.Domain.Identity;
using Triathlon.Web.Jobs;

namespace Triathlon.Web.Services;

/// <summary>One staff account as the Users screen shows it.</summary>
public sealed record StaffAccount(
    string Id, string Email, string? DisplayName, IReadOnlyList<string> Roles, bool Disabled);

/// <summary>
/// Staff accounts, created by an administrator and never self-registered.
/// <para>
/// No password is ever chosen, shown, mailed or written down: an invite creates the account with a
/// throwaway secret and the invitee sets their own through a reset link. Disabling is a permanent
/// lockout plus a security-stamp bump, so a live session is dropped at the next revalidation — which
/// is why <see cref="Areas.Dashboard.Account.IdentityRevalidatingAuthenticationStateProvider"/> runs
/// every five minutes rather than every thirty.
/// </para>
/// </summary>
public sealed class StaffAccounts(
    UserManager<AppUser> users, IActivityLogger activity, ICurrentUser currentUser, IBackgroundJobClient jobs)
{
    public async Task<IReadOnlyList<StaffAccount>> ListAsync(CancellationToken ct)
    {
        var accounts = new List<StaffAccount>();

        // A handful of staff, so one round trip per account is cheaper than joining the role tables
        // by hand and keeps the role names coming from Identity's own resolution.
        foreach (var user in users.Users.OrderBy(u => u.Email).ToList())
        {
            ct.ThrowIfCancellationRequested();
            accounts.Add(await DescribeAsync(user));
        }

        return accounts;
    }

    public async Task<StaffAccount> InviteAsync(string email, string? displayName, string role, CancellationToken ct)
    {
        ArgumentException.ThrowIfNullOrWhiteSpace(email);

        if (!Roles.All.Contains(role, StringComparer.Ordinal))
        {
            throw new ContentValidationException("Role", "Validation_Range");
        }

        var trimmed = email.Trim();
        if (await users.FindByEmailAsync(trimmed) is not null)
        {
            throw new ContentValidationException("Email", "Validation_DuplicateRow");
        }

        var user = new AppUser
        {
            UserName = trimmed,
            Email = trimmed,
            EmailConfirmed = true,
            DisplayName = string.IsNullOrWhiteSpace(displayName) ? null : displayName.Trim(),
        };

        // A password nobody will ever hold: generated here, used once to satisfy Identity's
        // create-with-password path, and never written down, shown or mailed. The invitee sets their
        // own through the reset link StaffMailJob sends.
        var throwaway = Convert.ToBase64String(
            System.Security.Cryptography.RandomNumberGenerator.GetBytes(24)) + "aA1!";

        var created = await users.CreateAsync(user, throwaway);
        if (!created.Succeeded)
        {
            throw new ContentValidationException("Email", "Validation_UserCreate", Describe(created));
        }

        var added = await users.AddToRoleAsync(user, role);
        if (!added.Succeeded)
        {
            await users.DeleteAsync(user);   // never leave a roleless account behind
            throw new ContentValidationException("Role", "Validation_UserCreate", Describe(added));
        }

        await activity.LogAsync("User", user.Id, "invite", null, new { user.Email, Role = role }, ct);

        // The job regenerates the reset token itself: a token in a Hangfire argument is a token in
        // the job store, readable by anyone with the dashboard or the database.
        jobs.Enqueue<StaffMailJob>(job => job.SendInviteAsync(user.Id, CancellationToken.None));

        return new StaffAccount(user.Id, user.Email!, user.DisplayName, [role], Disabled: false);
    }

    public async Task SetRoleAsync(string userId, string role, CancellationToken ct)
    {
        if (!Roles.All.Contains(role, StringComparer.Ordinal))
        {
            throw new ContentValidationException("Role", "Validation_Range");
        }

        var user = await Find(userId);
        await GuardSelfAsync(user);
        if (role != Roles.SuperAdmin)
        {
            await GuardLastAdminAsync(user);
        }

        var current = await users.GetRolesAsync(user);
        if (current.Count > 0)
        {
            var removed = await users.RemoveFromRolesAsync(user, current);
            if (!removed.Succeeded)
            {
                throw new ContentValidationException("Role", "Validation_UserCreate", Describe(removed));
            }
        }

        var added = await users.AddToRoleAsync(user, role);
        if (!added.Succeeded)
        {
            throw new ContentValidationException("Role", "Validation_UserCreate", Describe(added));
        }

        // A role change is a capability change; drop any live session so it is re-evaluated.
        await users.UpdateSecurityStampAsync(user);

        await activity.LogAsync("User", user.Id, "role", new { Roles = string.Join(',', current) },
            new { user.Email, Role = role }, ct);
    }

    public async Task SetEnabledAsync(string userId, bool enabled, CancellationToken ct)
    {
        var user = await Find(userId);
        await GuardSelfAsync(user);
        if (!enabled)
        {
            await GuardLastAdminAsync(user);
        }

        await users.SetLockoutEnabledAsync(user, true);

        // DateTimeOffset.MaxValue rather than a far-future date: "disabled" is not "locked out until
        // Tuesday", and Login.razor already sends a locked-out account to /dashboard/lockout.
        var result = await users.SetLockoutEndDateAsync(user, enabled ? null : DateTimeOffset.MaxValue);
        if (!result.Succeeded)
        {
            throw new ContentValidationException("Id", "Validation_UserCreate", Describe(result));
        }

        // A disabled account with a live cookie would otherwise keep working until the cookie
        // expired; bumping the stamp makes the revalidating authentication state provider drop the
        // circuit at its next check, which is five minutes.
        await users.UpdateSecurityStampAsync(user);

        await activity.LogAsync("User", user.Id, enabled ? "enable" : "disable", null, new { user.Email }, ct);
    }

    public async Task SendResetLinkAsync(string userId, CancellationToken ct)
    {
        var user = await Find(userId);

        await activity.LogAsync("User", user.Id, "resetLink", null, new { user.Email }, ct);

        jobs.Enqueue<StaffMailJob>(job => job.SendResetAsync(user.Id, CancellationToken.None));
    }

    private async Task<AppUser> Find(string userId) =>
        await users.FindByIdAsync(userId) ?? throw new ContentValidationException("Id", "Validation_NotFound");

    private async Task<StaffAccount> DescribeAsync(AppUser user) => new(
        user.Id, user.Email ?? user.UserName ?? "", user.DisplayName,
        [.. await users.GetRolesAsync(user)],
        user.LockoutEnd is { } end && end > DateTimeOffset.UtcNow);

    /// <summary>
    /// An administrator cannot lock themselves out or demote themselves: the recovery from either
    /// would be a database edit, and there is no second administrator to undo it in a one-admin
    /// federation. Changing your own password has its own page.
    /// </summary>
    private async Task GuardSelfAsync(AppUser user)
    {
        var acting = await currentUser.GetNameAsync();
        if (acting is not null
            && (string.Equals(acting, user.UserName, StringComparison.OrdinalIgnoreCase)
                || string.Equals(acting, user.Email, StringComparison.OrdinalIgnoreCase)))
        {
            throw new ContentValidationException("Id", "Validation_CannotChangeSelf");
        }
    }

    /// <summary>The site must always have one administrator who can still sign in.</summary>
    private async Task GuardLastAdminAsync(AppUser user)
    {
        if (!await users.IsInRoleAsync(user, Roles.SuperAdmin))
        {
            return;
        }

        var admins = await users.GetUsersInRoleAsync(Roles.SuperAdmin);
        var usable = admins.Count(a => a.LockoutEnd is null || a.LockoutEnd <= DateTimeOffset.UtcNow);

        if (usable <= 1)
        {
            throw new ContentValidationException("Role", "Validation_LastAdmin");
        }
    }

    private static string Describe(IdentityResult result) =>
        string.Join(" ", result.Errors.Select(e => e.Description));
}
```

```csharp
/// <summary>
/// Which capability may read which part of the audit trail. Every entity name this application ever
/// writes to <c>ActivityLog.Entity</c> is listed here by name — twenty of them, not an abbreviated
/// sample — because the feed is the one screen that shows every part of the system at once, and an
/// entity nobody has classified must not leak into it by accident. An unknown name is administrator
/// only, and <c>ActivityScopesTests</c> greps the source for every <c>ApplyAsync("X"</c> and
/// <c>LogAsync("X"</c> literal, so the build fails the day a twenty-first is added without a line here.
/// </summary>
public static class ActivityScopes
{
    public static readonly IReadOnlyDictionary<string, string> EntityPolicies =
        new Dictionary<string, string>(StringComparer.Ordinal)
        {
            // The membership desk's own records.
            ["Athlete"] = Policies.Crm,
            ["Contact"] = Policies.Crm,
            ["EmailBlast"] = Policies.Crm,
            ["EventRegistration"] = Policies.Crm,

            // Everything an editor publishes. Club is content because the club list renders on the
            // public join and training pages and ContentService owns its cache eviction.
            ["City"] = Policies.Content,
            ["Club"] = Policies.Content,
            ["Committee"] = Policies.Content,
            ["Document"] = Policies.Content,
            ["Event"] = Policies.Content,
            ["GrowthPoint"] = Policies.Content,
            ["Kpi"] = Policies.Content,
            ["MediaAsset"] = Policies.Content,
            ["Navigation"] = Policies.Content,
            ["NewsPost"] = Policies.Content,
            ["Page"] = Policies.Content,
            ["RegionStat"] = Policies.Content,
            ["Rule"] = Policies.Content,
            ["TrainingGuide"] = Policies.Content,

            // Configuration and accounts.
            ["SiteSetting"] = Policies.Admin,
            ["User"] = Policies.Admin,
        };

    public static string PolicyFor(string entity) =>
        EntityPolicies.TryGetValue(entity, out var policy) ? policy : Policies.Admin;

    /// <summary>
    /// The entity names a caller with these capabilities may read, in a stable order. All three false
    /// returns an empty list, and <c>ActivityQuery.FeedAsync</c> reads that as "nothing", never as
    /// "no filter" — fail closed.
    /// </summary>
    public static IReadOnlyList<string> VisibleTo(bool content, bool crm, bool admin)
    {
        var allowed = new List<string>();

        foreach (var (entity, policy) in EntityPolicies.OrderBy(pair => pair.Key, StringComparer.Ordinal))
        {
            var visible = policy switch
            {
                Policies.Content => content,
                Policies.Crm => crm,
                _ => admin,
            };

            if (visible)
            {
                allowed.Add(entity);
            }
        }

        return allowed;
    }
}
```

```csharp
using System.Globalization;
using System.Security.Cryptography;
using Microsoft.AspNetCore.DataProtection;
using Microsoft.Extensions.Options;
using Triathlon.Web.Data.Crm;
using Triathlon.Web.Infrastructure;

namespace Triathlon.Web.Services;

/// <summary>
/// A short-lived link that lets an editor show a colleague an unpublished page, news post or event.
/// The token <em>is</em> the authorisation: thirty minutes of read access to one draft record is the
/// right trade for not building a second permission system.
/// <para>
/// The expiry is a Unix timestamp inside the protected payload, checked against the injected
/// <see cref="TimeProvider"/> — deliberately not <c>ToTimeLimitedDataProtector</c>, which keeps its own
/// internal clock that a test with a <c>FakeTimeProvider</c> could never advance past. Tamper-proofing
/// comes from data protection either way; what this buys is a lifetime the suite can actually prove.
/// </para>
/// </summary>
public sealed class PreviewTokens(IDataProtectionProvider provider, IOptions<SiteOptions> site, TimeProvider clock)
{
    public static readonly TimeSpan Lifetime = TimeSpan.FromMinutes(30);

    private readonly IDataProtector _protector = provider.CreateProtector(CrmProtection.PreviewPurpose);

    public string Create(string entity, Guid id)
    {
        var expires = clock.GetUtcNow().Add(Lifetime).ToUnixTimeSeconds();

        return _protector.Protect(string.Create(CultureInfo.InvariantCulture, $"{entity}:{id:N}:{expires}"));
    }

    public bool TryRead(string? token, out string entity, out Guid id)
    {
        entity = "";
        id = Guid.Empty;

        if (string.IsNullOrWhiteSpace(token))
        {
            return false;
        }

        string payload;
        try
        {
            payload = _protector.Unprotect(token);
        }
        catch (CryptographicException)
        {
            return false;
        }
        catch (FormatException)
        {
            return false;
        }

        var parts = payload.Split(':', 3);
        if (parts.Length != 3
            || !Guid.TryParseExact(parts[1], "N", out id)
            || !long.TryParse(parts[2], CultureInfo.InvariantCulture, out var expires))
        {
            id = Guid.Empty;
            return false;
        }

        if (DateTimeOffset.FromUnixTimeSeconds(expires) <= clock.GetUtcNow())
        {
            id = Guid.Empty;
            return false;
        }

        entity = parts[0];
        return true;
    }

    public string Link(string entity, Guid id, string culture) =>
        $"{site.Value.BaseUrl.TrimEnd('/')}/{(culture == "ar" ? "ar" : "en")}/preview/{Create(entity, id)}";
}
```

```csharp
    /// <summary>
    /// Removes a soft-deleted asset for good: the catalog row and the files behind it. Refuses while
    /// any content still points at the path — there is no foreign key from that side, so this check is
    /// the only thing standing between an editor and a broken image on a published page.
    /// </summary>
    public async Task PurgeAsync(Guid id, CancellationToken ct)
    {
        var asset = await db.MediaAssets.IgnoreQueryFilters().SingleOrDefaultAsync(a => a.Id == id, ct)
            ?? throw new ContentValidationException("Id", "Validation_NotFound");

        // Deleting is the first step and purging the second, deliberately: an asset has to be visibly
        // out of the library for a while before it can be destroyed.
        if (asset.DeletedAt is null)
        {
            throw new ContentValidationException("Id", "Validation_MediaNotDeleted");
        }

        if (await IsReferencedAsync(asset.Path, ct))
        {
            throw new ContentValidationException("Id", "Validation_MediaInUse");
        }

        var before = Audit.Snapshot(asset);
        db.MediaAssets.Remove(asset);
        db.Entry(asset).State = EntityState.Deleted;   // a real delete, not StampInterceptor's soft one

        await commit.ApplyAsync("MediaAsset", id, "purge", before, null, [], ct);

        // After the commit, never before: a file removed for a save that then failed is unrecoverable.
        await store.DeleteAsync(asset.Path, ct);
    }

    /// <summary>Every place an editor can point at a stored file. Add to this list when a new one appears.</summary>
    private async Task<bool> IsReferencedAsync(string path, CancellationToken ct) =>
        await db.Documents.IgnoreQueryFilters().AnyAsync(d => d.FilePath == path, ct)
        || await db.Rules.IgnoreQueryFilters().AnyAsync(r => r.FilePath == path, ct)
        || await db.TrainingGuides.IgnoreQueryFilters().AnyAsync(g => g.FilePath == path, ct)
        || await db.Events.IgnoreQueryFilters().AnyAsync(e => e.HeroImagePath == path || e.ResultsFilePath == path, ct)
        || await db.EventGalleryImages.IgnoreQueryFilters().AnyAsync(i => i.Path == path, ct)
        || await db.NewsPosts.IgnoreQueryFilters().AnyAsync(n => n.HeroImagePath == path, ct)
        || await db.PageBlocks.IgnoreQueryFilters().AnyAsync(b =>
            (b.BodyEn != null && b.BodyEn.Contains(path))
            || (b.BodyAr != null && b.BodyAr.Contains(path))
            || b.ItemsJson.Contains(path), ct);

    /// <summary>
    /// Files under the media root with no catalog row. Reported, never deleted: a file this method
    /// does not recognise may be one somebody copied in on purpose, and a nightly job that removes
    /// data is a job nobody sleeps through.
    /// </summary>
    public async Task<IReadOnlyList<string>> OrphanFilesAsync(CancellationToken ct)
    {
        var root = options.Value.ResolveRoot(environment);
        if (!Directory.Exists(root))
        {
            return [];
        }

        var known = new HashSet<string>(
            await db.MediaAssets.IgnoreQueryFilters().Select(a => a.Path).ToListAsync(ct),
            StringComparer.Ordinal);

        // Variants are derived from an original and are not catalog rows of their own.
        foreach (var asset in await db.MediaAssets.IgnoreQueryFilters().Select(a => a.VariantsJson).ToListAsync(ct))
        {
            foreach (var variant in JsonSerializer.Deserialize<List<string>>(asset) ?? [])
            {
                known.Add(variant);
            }
        }

        var prefix = options.Value.NormalizedPublicPrefix;

        return
        [
            .. Directory.EnumerateFiles(root, "*.*", SearchOption.AllDirectories)
                .Select(file => prefix + "/" + Path.GetRelativePath(root, file).Replace(Path.DirectorySeparatorChar, '/'))
                .Where(path => !known.Contains(path))
                .Order(StringComparer.Ordinal),
        ];
    }
```
